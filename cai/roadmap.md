## 一、核心思路

**一句话**：先在模拟环境里炼化庄家-彩民对抗智能体，再让它们去真实彩票数据上输出预测，同时用纯深度学习做对照，比较两者差异，判断"庄家偏置"是否存在。

### 设计哲学

- **模拟环境是理论生成器**——如果庄家偏置存在，它会在对抗博弈中自然涌现
- **实盘数据是理论检验器**——模拟训练出的策略能否在真实数据上表现优于纯随机学习？
- **信息对称原则**：现实彩民的公开信息 = 模拟中彩民智能体的信息输入，保持一致性
- **可证伪性**：实验设计必须允许 H₀（纯随机）为真的情况，且有能力报告 null result

### 逻辑链

```
如果庄家偏置存在
  → 模拟环境中的对抗学习能捕获偏置模式
  → 训练后的策略在真实数据上优于纯DL基线
  → 两组预测得分差异统计显著
如果庄家偏置不存在
  → 对抗学习捕获的是模拟噪声，无法泛化
  → 两组预测得分无显著差异
  → Null result：这也是有价值的科学结论
```

## 三、对照组：纯深度学习基线

### 定位

假设开奖完全随机，模型只能从历史序列中学习——如果序列本身无可学模式，模型退化为近似均匀分布。这是实验的**地板**（floor），任何声称"有效"的方法都必须显著超过它。

### 设计

| 项目 | 说明 |
|------|------|
| 彩种 | 排列3 / 福彩3D（首选）；双色球 / 大乐透（次选交叉验证） |
| 输入 | 历史N期开奖号码序列（滑动窗口，N=30/60/100 待调参） |
| 模型 | LSTM (2层, hidden=128) / Transformer (4头, 2层) |
| 输出 | 下一期号码的概率分布（排列3: 1000维 softmax） |
| 训练 | 标准监督学习，交叉熵损失，Adam优化 |
| 预测 | 取概率最高的k个号码作为推荐（k=1/5/10） |
| 评估指标 | Top-k命中率、NLL、Brier Score |

### 实现细节

```python
# 对照组模型示意
class DLBaseline(nn.Module):
    def __init__(self, vocab_size=1000, d_model=128, nhead=4, num_layers=2):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, d_model)
        self.transformer = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d_model, nhead, batch_first=True),
            num_layers=num_layers
        )
        self.fc = nn.Linear(d_model, vocab_size)

    def forward(self, x):  # x: [batch, seq_len] 整数序列
        emb = self.embedding(x)          # [batch, seq_len, d_model]
        out = self.transformer(emb)       # [batch, seq_len, d_model]
        logits = self.fc(out[:, -1, :])   # [batch, vocab_size] 取最后时刻
        return logits
```

### 本质

纯"从数据到数据"的端到端学习，不含任何关于博弈结构的先验知识。如果开奖是纯随机的，这个模型的输出应该接近均匀分布，Top-k命中率 ≈ k/1000。

## 四、实验组：对抗学习模拟

### 4.1 模拟环境：虚拟彩票生态

**彩种选择：排列3 / 福彩3D**

- 3位数字，000-999，共1000种组合
- 每日开奖，数据量大（排列3自2005年起，约7500+期；福彩3D自2004年起，约8000+期）
- 结构最简单，模拟开销最小
- 规则完全参照真实规则：直选1040元、组选3（346元）、组选6（173元）
- **为什么不首选双色球**：号码空间 C(33,6)×16 ≈ 1772万，模拟中的投注分布过于稀疏，彩民策略空间也过大，对计算资源和训练时间要求极高。先在排列3跑通 pipeline，再迁移到双色球做交叉验证。

**模拟环境参数**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 彩民总数 | 1000 | 每期参与投注的模拟彩民数 |
| 随机型比例 | 65% | 对应现实中的机选/随手填 |
| 策略型比例 | 35% | 对应现实中的"技术型彩民" |
| 庄家偏置强度 β | 0.1~1.0 | 温度采样参数，β=0纯随机 |
| 每期模拟时长 | ~1ms | 纯Python，1000个agent |
| 总模拟期数 | ≥5000 | 需要power analysis确定 |

### 4.2 彩民智能体

#### 4.2.1 类型与比例

| 类型 | 占比 | 选号方式 | 信息输入 |
|------|------|----------|----------|
| **随机型** | 60-70% | 均匀随机选号 | 无（模拟现实中机器自选） |
| **策略型** | 30-40% | 基于信息决策 | 与现实中彩民可获取的公开信息一致 |

> **60-70%随机型的现实依据**：中国彩票实际销售中，多数彩民选择机选或随手填写，系统性研究号码的"技术型彩民"是少数。此比例参照行业经验估算，正式实验中应做灵敏度分析。

#### 4.2.2 策略型彩民的可用信息

与现实彩民完全一致——现实中彩民能查到什么，模拟中的策略型彩民就能看到什么：

| 信息类型 | 具体内容 | 对应现实来源 | 模拟中的获取方式 |
|----------|----------|-------------|-----------------|
| 历史开奖记录 | 过去N期的开奖号码 | 官网/500彩票网等 | 环境直接提供 |
| 号码频率统计 | 各数字出现次数/频率 | 走势图 | 从历史数据计算 |
| 冷热号分析 | 近期高频/低频号码 | 彩票分析软件 | 滑动窗口统计 |
| 遗漏值 | 各号码连续未出期数 | 走势图 | 从历史数据计算 |
| 奇偶/大小/和值 | 统计特征 | 彩民论坛/分析工具 | 从历史数据计算 |
| 全国总销量 | 每期销售总额 | 开奖公告 | 环境提供（模拟值） |

**不可获取的信息**（与现实一致）：
- ❌ 其他彩民的具体投注选择
- ❌ 庄家的内部策略/偏置参数
- ❌ 各号码的具体投注量分布

> **信息不对称是实验的核心张力**：庄家看到全局投注分布，彩民只能看到公开信息。这种不对称驱动了整个对抗博弈。

#### 4.2.3 策略型彩民的决策模型——多流派混合方案

采用**方案C：多流派规则 + 轻量网络混合**，贴近现实彩民行为多样性：

| 流派 | 核心策略 | 占策略型比例 | 实现方式 |
|------|----------|-------------|----------|
| **追热派** | 偏好近期高频号 | ~30% | 规则：选近20期出现频率Top-30的号 |
| **追冷派** | 偏好长期未出的号 | ~25% | 规则：选遗漏值Top-30的号 |
| **和值派** | 关注三位数字之和 | ~15% | 规则：限定和值区间[10,17]，内部随机 |
| **走势派** | 基于近期走势推断 | ~20% | 轻量LSTM：输入近10期，输出概率分布 |
| **混合派** | 综合多种信号 | ~10% | 加权融合上述信号 |

```python
# 策略型彩民示意
class StrategyPlayer:
    def __init__(self, strategy_type, window=20):
        self.strategy_type = strategy_type
        self.window = window

    def choose(self, history, sales_data):
        """history: list of past draws, sales_data: dict"""
        if self.strategy_type == 'hot':
            freq = self._compute_freq(history[-self.window:])
            candidates = sorted(range(1000), key=lambda x: freq[x], reverse=True)[:30]
        elif self.strategy_type == 'cold':
            miss = self._compute_missing(history[-self.window:])
            candidates = sorted(range(1000), key=lambda x: miss[x], reverse=True)[:30]
        elif self.strategy_type == 'sum':
            candidates = [n for n in range(1000) if 10 <= sum(int(d) for d in f"{n:03d}") <= 17]
        elif self.strategy_type == 'trend':
            candidates = self._lstm_predict(history)  # 轻量LSTM
        elif self.strategy_type == 'mixed':
            candidates = self._ensemble(history, sales_data)
        return random.choice(candidates)
```

> **为什么不用纯RL**：RL agent训练开销大、收敛不稳定，且学到的策略可能高度抽象，不像真实彩民。多流派规则更贴近现实，也便于分析"哪种类型的彩民最先被庄家'吃掉'"。

### 4.3 庄家智能体

#### 4.3.1 信息优势

庄家能看到全局投注分布——这与现实一致（彩票中心掌握所有销售数据）：

| 信息 | 说明 |
|------|------|
| 各号码投注量 | 全局视角，知道哪些号码买的人多/少 |
| 总销售额 | 保险绳：赔付不能超过收入 |
| 历史开奖记录 | 同彩民 |
| 彩民类型分布估计 | 可选：庄家可以尝试推断彩民群体结构 |

#### 4.3.2 目标

**最小化赔付**——在"看起来随机"的前提下，倾向于开出少人买的号码。

#### 4.3.3 约束

庄家不能公然造假，否则会被统计检验检测到。因此：
- 开奖结果必须"近似随机"——能通过基本的随机性检验（χ²、游程检验等）
- 偏置是微妙的、持续的，而非极端的
- 庄家的策略也应该是可学习的——如果庄家太聪明，就变成了一方碾压，失去了博弈的张力

#### 4.3.4 实现方式——温度采样（推荐方案C）

$$P(\text{号码}i) = \frac{\exp(-\beta \times \text{投注量}_i)}{\sum_{j} \exp(-\beta \times \text{投注量}_j)}$$

| 参数 | 含义 | 效果 |
|------|------|------|
| β = 0 | 纯均匀随机 | 庄家不偏置，退化为真实随机 |
| β = 0.1 | 微弱偏置 | 热门号概率略降，冷门号略升 |
| β = 0.5 | 中等偏置 | 偏置可被统计检验检测 |
| β = 1.0 | 强偏置 | 偏置明显，庄家行为可能被感知 |

**为什么选温度采样**：
1. **连续可调**：β是一个连续参数，可以做灵敏度分析
2. **优雅退化**：β=0时退化为纯随机，不需要额外逻辑
3. **可解释**：β就是"庄家有多大胆"的量化
4. **计算简单**：一行代码实现，不需要训练RL

```python
# 庄家开奖示意
class Bookmaker:
    def __init__(self, beta=0.3):
        self.beta = beta

    def draw(self, bet_distribution):
        """
        bet_distribution: array[1000], 每个号码的投注量
        返回: 开奖号码 (0-999)
        """
        logits = -self.beta * bet_distribution
        probs = softmax(logits)
        return np.random.choice(1000, p=probs)
```

#### 4.3.5 备选方案：RL庄家

如果温度采样太"静态"（庄家不会根据彩民策略的变化而调整），可以升级为RL庄家：

| 方案 | 描述 | 优劣 |
|------|------|------|
| A: 偏置采样 | ε概率选冷门号，1-ε随机 | 简单但不灵活 |
| B: 温度采样 | 上述方案C | 优雅、连续可调、推荐首选 |
| C: RL agent | state=投注分布+历史，action=选择号码，reward=-赔付 | 最灵活，但action空间大（1000），收敛困难 |

> **推荐路线**：先用温度采样跑通整个pipeline，确认实验框架可用后，再尝试RL庄家做对比。RL庄家的action空间可以用层级采样缩小（先选百位→十位→个位）。

### 4.4 对抗训练循环

```python
class AdversarialSimulation:
    def __init__(self, n_players=1000, random_ratio=0.65, beta=0.3):
        self.players = self._init_players(n_players, random_ratio)
        self.bookmaker = Bookmaker(beta=beta)
        self.history = []          # 开奖历史
        self.bet_history = []      # 投注分布历史
        self.reward_history = []   # 收益历史

    def run_episode(self):
        # 1. 彩民选号
        bets = np.zeros(1000)
        for player in self.players:
            if player.type == 'random':
                choice = np.random.randint(1000)
            else:
                choice = player.choose(self.history, self.sales_info)
            bets[choice] += 1  # 简化：每人一注

        # 2. 庄家开奖
        draw = self.bookmaker.draw(bets)

        # 3. 结算
        total_payout = self._calculate_payout(bets, draw)
        for player in self.players:
            player.reward = self._player_payout(player.bet, draw)

        # 4. 更新策略（策略型彩民）
        for player in self.players:
            if player.type != 'random':
                player.update_policy()

        # 5. 记录
        self.history.append(draw)
        self.bet_history.append(bets.copy())
        self.reward_history.append({
            'draw': draw,
            'total_payout': total_payout,
            'total_sales': bets.sum() * 2,  # 每注2元
            'payout_rate': total_payout / (bets.sum() * 2)
        })

    def run(self, n_episodes=5000):
        for ep in range(n_episodes):
            self.run_episode()
            if ep % 100 == 0:
                self._check_convergence()
        return self.history, self.bet_history, self.reward_history
```

### 4.5 收敛判断

收敛指标（需同时满足）：

| 指标 | 判定标准 | 检测方式 |
|------|----------|----------|
| 庄家β稳定性 | β估计值滑动平均方差 < 阈值 | 每100期估计β，计算滑动方差 |
| 彩民策略分布 | 选号分布的KL散度 < 阈值 | 与前100期比较 |
| 平均赔付率 | 滑动平均波动 < 1% | 最近500期的赔付率标准差 |
| 各流派彩民存活率 | 不再发生大规模"灭绝" | 追踪各流派比例变化 |

可视化要求：
- 赔付率曲线（500期滑动平均）
- 投注分布热力图（每1000期一帧）
- 各流派彩民收益率对比
- 庄家偏置强度β的估计值变化

### 4.6 正向对照实验（必须做）

**目的**：验证我们的方法论确实能检测到偏置——如果连已知偏置都检测不到，那检测不到真实偏置也不能说明什么。

**方法**：
1. 用温度采样生成带已知β的合成开奖数据
2. 用同样的对照组DL vs 实验组对抗学习进行分析
3. 检验：在已知偏置存在的条件下，我们的方法能否显著检测到？

| 合成数据β | 预期结论 |
|-----------|----------|
| β=0 (纯随机) | 两组无差异（验证H₀情况） |
| β=0.1 (微弱) | 方法能否检测到？→ 灵敏度下限 |
| β=0.5 (中等) | 应能检测到 |
| β=1.0 (强) | 必须能检测到，否则方法有问题 |

**数据划分**：
- 训练集：前80%（对照组DL训练用；模拟环境参考其统计特性）
- 测试集：后20%（两组共同预测，比较差异）
- **注意**：模拟环境不使用真实数据训练，它完全自洽地运行；真实数据只在最后检验阶段使用

### 5.2 预测方式

| 组别 | 预测逻辑 |
|------|----------|
| 对照组 | DL模型 → 给定历史N期 → 输出概率分布 → 取Top-k |
| 实验组 | 模拟训练后的策略 → 给定真实历史数据 → 彩民agent选号 → 输出推荐号码 |

**实验组的关键问题**：模拟环境训练出的策略如何处理真实数据？

1. **策略迁移**：策略型彩民的规则/轻量网络直接读入真实历史数据，按训练好的策略输出选号
2. **信息适配**：真实数据中的历史开奖、频率统计等 → 转换为模拟环境中彩民的信息格式
3. **不需要庄家**：实盘预测阶段不需要庄家（我们无法影响真实开奖），只需要彩民策略

### 5.3 统计检验

#### 检验方案

| 步骤 | 方法 | 目的 |
|------|------|------|
| 1 | Top-k命中率比较 | 直观评估 |
| 2 | 配对 t 检验 | 每期一个样本，比较两组的预测得分 |
| 3 | Wilcoxon 符号秩检验 | 非参数替代（不假设正态） |
| 4 | 效应量估计 (Cohen's d) | 不仅问"是否显著"，还问"差异多大" |
| 5 | 多重比较校正 (Bonferroni) | 多彩种检验时控制总体α |
| 6 | Bootstrap 置信区间 | 稳健估计 |

#### 统计功效 (Power Analysis)

在做检验前，需要估算所需样本量：

```python
from statsmodels.stats.power import TTestPower
power_analysis = TTestPower()
# 假设效应量 d=0.2（小效应），α=0.05，power=0.8
n_required = power_analysis.solve_power(effect_size=0.2, alpha=0.05, power=0.8)
# n ≈ 198 期 → 排列3约200天数据，可行
```

> 如果效应量极小（d<0.1），可能需要 >1000期测试数据，这时需要考虑数据是否足够。

### 5.4 结果解读

| 结果 | 含义 | 下一步 |
|------|------|--------|
| 实验组显著优于对照组 | 支持都市传说——对抗博弈捕获了真实存在的庄家偏置模式 | 进一步分析偏置的模式特征 |
| 两组无显著差异 | 不支持——但需排除统计功效不足 | 报告效应量上限，讨论灵敏度 |
| 两组都优于随机基线 | 开奖序列本身存在可学模式（重大发现） | 分析学到的模式是什么 |
| 两组都不优于随机 | 开奖确实是纯随机的——null result | 报告方法论灵敏度，讨论检测极限 |

> **Null Result 处理原则**：null result 不等于实验失败。如果我们的方法论经过正向对照验证（能检测到已知偏置），但在真实数据上检测不到，这恰恰是"彩票是纯随机的"的强证据。
