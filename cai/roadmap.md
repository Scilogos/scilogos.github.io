# 财略 · 彩票博弈 — 初步思路大纲

> 量化经济与行为课程 Project · 对抗学习模拟 + 实盘验证
> v0.1 · 2026-06-15

---

## 一、核心思路

**一句话**：先在模拟环境里炼化庄家-彩民对抗智能体，再让它们去真实彩票数据上输出预测，同时用纯深度学习做对照，比较两者差异，判断"庄家偏置"是否存在。

### 设计哲学

- 模拟环境是**理论生成器**——如果庄家偏置存在，它会在对抗博弈中自然涌现
- 实盘数据是**理论检验器**——模拟训练出的策略能否在真实数据上表现优于纯随机学习？
- 现实彩民的公开信息 = 模拟中彩民智能体的信息输入，保持信息对称的一致性

## 三、对照组：纯深度学习基线

### 定位
假设开奖完全随机，模型只能从历史序列中学习——如果序列本身无可学模式，模型退化为近似均匀分布。

### 设计
| 项目 | 说明 |
|------|------|
| 彩种 | 排列3 / 福彪3D（首选）；双色球 / 大乐透（次选交叉验证） |
| 输入 | 历史N期开奖号码序列（滑动窗口） |
| 模型 | LSTM / Transformer |
| 输出 | 下一期号码的概率分布（1000维 softmax） |
| 训练 | 标准监督学习，交叉熵损失 |
| 预测 | 取概率最高的k个号码作为推荐 |

### 本质
纯"从数据到数据"的端到端学习，不含任何关于博弈结构的先验知识。

## 四、实验组：对抗学习模拟

### 4.1 模拟环境：虚拟彩票生态

**彩种选择：排列3 / 福彩3D**
- 3位数字，000-999，共1000种组合
- 每日开奖，数据量大
- 结构最简单，模拟开销最小
- 规则完全参照真实规则：直选1040元、组选3（346元）、组选6（173元）

### 4.2 彩民智能体

#### 4.2.1 类型与比例

| 类型 | 占比 | 选号方式 | 信息输入 |
|------|------|----------|----------|
| **随机型** | 60-70% | 均匀随机选号 | 无（模拟现实中机器自选） |
| **策略型** | 30-40% | 基于信息决策 | 与现实中彩民可获取的公开信息一致 |

> **60-70%随机型的现实依据**：中国彩票实际销售中，多数彩民选择机选或随手填写，系统性研究号码的"技术型彩民"是少数。

#### 4.2.2 策略型彩民的可用信息

与现实彩民完全一致——现实中彩民能查到什么，模拟中的策略型彩民就能看到什么：

| 信息类型 | 具体内容 | 对应现实来源 |
|----------|----------|-------------|
| 历史开奖记录 | 过去N期的开奖号码 | 官网/500彩票网等 |
| 号码频率统计 | 各数字出现次数/频率 | 走势图 |
| 冷热号分析 | 近期高频/低频号码 | 彩票分析软件 |
| 遗漏值 | 各号码连续未出期数 | 走势图 |
| 奇偶/大小/和值 | 统计特征 | 彩民论坛/分析工具 |
| 全国总销量 | 每期销售总额 | 开奖公告 |

**不可获取的信息**（与现实一致）：
- ❌ 其他彩民的具体投注选择
- ❌ 庄家的内部策略/偏置参数
- ❌ 各号码的具体投注量分布

#### 4.2.3 策略型彩民的决策模型

待定，候选方案：
- **方案A**：简单规则（偏好热号/冷号/和值区间）→ 容易实现，但不够"智能"
- **方案B**：小型RL agent，reward = 累计收益 → 更灵活，但训练开销大
- **方案C**：混合——部分用规则，部分用简单网络 → 折中

> 初步倾向方案C：策略型彩民分多种"流派"（追热派、追冷派、和值派等），用规则+轻量网络的混合实现，更贴近现实中彩民行为的多样性。

### 4.3 庄家智能体

#### 4.3.1 信息优势

庄家能看到全局投注分布——这与现实一致（彩票中心掌握所有销售数据）：

| 信息 | 说明 |
|------|------|
| 各号码投注量 | 全局视角，知道哪些号码买的人多/少 |
| 总销售额 | 保险绳：赔付不能超过收入 |
| 历史开奖记录 | 同彩民 |

#### 4.3.2 目标

**最小化赔付**——在"看起来随机"的前提下，倾向于开出少人买的号码。

#### 4.3.3 约束

庄家不能公然造假，否则会被统计检验检测到。因此：
- 开奖结果必须"近似随机"——能通过基本的随机性检验
- 偏置是微妙的、持续的，而非极端的

#### 4.3.4 实现方式

待定，候选方案：

| 方案 | 描述 | 优劣 |
|------|------|------|
| **A: 偏置采样** | 真随机基础上，按投注量反比调整各号码被选中的概率 | 简单直接，偏置强度可调（ε参数） |
| **B: RL agent** | 庄家是RL agent，state=投注分布，action=选择号码，reward=-赔付 | 最灵活，但离散action空间大 |
| **C: 温度采样** | 用投注量的倒数作为logits，温度参数控制偏置强度 | 优雅，连续可调 |

> 初步倾向方案C：`P(号码i) ∝ exp(-β × 投注量_i)`，β=0时退化为均匀随机，β越大偏置越强。这样β本身就是一个可研究的参数——"庄家有多大胆？"

### 4.4 对抗训练循环

```
for episode in range(N_EPOCHS):
    # 1. 彩民选号
    for player in players:
        if player.type == 'random':
            player.bet = random_choice()           # 60-70%
        else:
            player.bet = strategy(player.info)      # 30-40%

    # 2. 汇总投注分布
    bet_distribution = aggregate(all_players.bets)

    # 3. 庄家开奖
    draw = bookmaker.draw(bet_distribution, beta)

    # 4. 结算
    for player in players:
        player.reward = payout(player.bet, draw)
    bookmaker.reward = -total_payout

    # 5. 更新策略
    for player in strategy_players:
        player.update_policy()
    bookmaker.update_policy()  # 如果用RL的话

    # 6. 记录 & 收敛检测
    log(bet_distribution, draw, rewards)
    if converged(): break
```

### 4.5 收敛判断

- 庄家策略的β（偏置强度）是否稳定
- 彩民策略的选号分布是否稳定
- 平均赔付率是否稳定
- 可视化：每100期滑动平均的赔付率曲线

## 五、实盘验证

### 5.1 数据

| 数据 | 来源 | 用途 |
|------|------|------|
| 排列3 历史数据 | 体彩API / 500彩票网 | 对照组训练 + 共同测试集 |
| 福彩3D 历史数据 | 福彩API | 交叉验证 |
| 双色球 历史数据 | 福彩API | 次选彩种验证 |

数据划分：
- 训练集：前80%（对照组DL训练用）
- 测试集：后20%（两组共同预测，比较差异）

### 5.2 预测方式

| 组别 | 预测逻辑 |
|------|----------|
| 对照组 | DL模型 → 给定历史N期 → 输出概率分布 → 取Top-k |
| 实验组 | 模拟训练后的策略 → 给定真实历史数据 → 彩民agent选号 → 输出推荐号码 |

### 5.3 统计检验

1. **预测准确率比较**：两组在测试集上各期预测的命中率
2. **配对 t 检验**：每期作为一个样本，比较两组的预测得分
3. **Wilcoxon 符号秩检验**：非参数替代
4. **效应量估计**：Cohen's d
5. **多彩种交叉验证**：排列3/3D/双色球分别做，看结论是否一致

### 5.4 结果解读

| 结果 | 含义 |
|------|------|
| 实验组显著优于对照组 | 支持都市传说——对抗博弈捕获了真实存在的庄家偏置模式 |
| 两组无显著差异 | 不支持——但需排除统计功效不足的可能 |
| 两组都优于随机基线 | 开奖序列本身存在可学模式（这本身就是重大发现） |
| 两组都不优于随机 | 开奖确实是纯随机的——null result，也是有价值的科学结论 |

## 七、关键待决问题

1. **庄家偏置的实现**：偏置采样 vs 温度采样 vs RL？→ 建议先用温度采样（方案C）跑通pipeline，再对比RL
2. **策略型彩民的决策模型**：规则流派 vs RL agent？→ 建议先用多流派规则（方案C），降低训练复杂度
3. **模拟多少期**：需要 power analysis 决定，初步建议 ≥ 5000期
4. **β（偏置强度）的合理范围**：需要先做灵敏度分析——β太小时差异不可检测，β太大时不现实
5. **迁移方式**：模拟训练的策略直接用于实盘？还是先在真实数据上 fine-tune？
6. **是否需要正向对照**：用带已知偏置的合成数据验证方法论 → 强烈建议加上
7. **课程截止日期 & 交付形式**：影响整体时间规划
